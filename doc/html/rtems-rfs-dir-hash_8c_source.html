46 /*
47  -------------------------------------------------------------------------------
48  mix -- mix 3 32-bit values reversibly.
49 
50  This is reversible, so any information in (a,b,c) before mix() is still in
51  (a,b,c) after mix().
52 
53  If four pairs of (a,b,c) inputs are run through mix(), or through mix() in
54  reverse, there are at least 32 bits of the output that are sometimes the same
55  for one pair and different for another pair. This was tested for:
56 
57  * pairs that differed by one bit, by two bits, in any combination of top bits
58  of (a,b,c), or in any combination of bottom bits of (a,b,c).
59 
60  * "differ" is defined as +, -, ^, or ~^. For + and -, I transformed the
61  output delta to a Gray code (a^(a>>1)) so a string of 1's (as is commonly
62  produced by subtraction) look like a single 1-bit difference.
63 
64  * the base values were pseudorandom, all zero but one bit set, or all zero
65  plus a counter that starts at zero.
66 
67  Some k values for my "a-=c; a^=rot(c,k); c+=b;" arrangement that satisfy this
68  are:
69 
70  4 6 8 16 19 4
71  9 15 3 18 27 15
72  14 9 3 7 17 3
73 
74  Well, "9 15 3 18 27 15" didn't quite get 32 bits diffing for "differ" defined
75  as + with a one-bit base and a two-bit delta. I used
76  http://burtleburtle.net/bob/hash/avalanche.html to choose the operations,
77  constants, and arrangements of the variables.
78 
79  This does not achieve avalanche. There are input bits of (a,b,c) that fail
80  to affect some output bits of (a,b,c), especially of a. The most thoroughly
81  mixed value is c, but it doesn't really even achieve avalanche in c.
82 
83  This allows some parallelism. Read-after-writes are good at doubling the
84  number of bits affected, so the goal of mixing pulls in the opposite
85  direction as the goal of parallelism. I did what I could. Rotates seem to
86  cost as much as shifts on every machine I could lay my hands on, and rotates
87  are much kinder to the top and bottom bits, so I used rotates.
88  -------------------------------------------------------------------------------
89 */
90 #define mix(a,b,c) \
91  { \
92  a -= c; a ^= rot(c, 4); c += b; \
93  b -= a; b ^= rot(a, 6); a += c; \
94  c -= b; c ^= rot(b, 8); b += a; \
95  a -= c; a ^= rot(c,16); c += b; \
96  b -= a; b ^= rot(a,19); a += c; \
97  c -= b; c ^= rot(b, 4); b += a; \
98  }

101  -------------------------------------------------------------------------------
102  final -- final mixing of 3 32-bit values (a,b,c) into c
103 
104  Pairs of (a,b,c) values differing in only a few bits will usually produce
105  values of c that look totally different. This was tested for
106 
107  * pairs that differed by one bit, by two bits, in any combination of top bits
108  of (a,b,c), or in any combination of bottom bits of (a,b,c).
109 
110  * "differ" is defined as +, -, ^, or ~^. For + and -, I transformed the
111  output delta to a Gray code (a^(a>>1)) so a string of 1's (as is commonly
112  produced by subtraction) look like a single 1-bit difference. * the base
113  values were pseudorandom, all zero but one bit set, or all zero plus a
114  counter that starts at zero.
115 
116  These constants passed:
117  14 11 25 16 4 14 24
118  12 14 25 16 4 14 24
119  and these came close:
120  4 8 15 26 3 22 24
121  10 8 15 26 3 22 24
122  11 8 15 26 3 22 24
123  -------------------------------------------------------------------------------
124 */
125 #define final(a,b,c) \
126  { \
127  c ^= b; c -= rot(b,14); \
128  a ^= c; a -= rot(c,11); \
